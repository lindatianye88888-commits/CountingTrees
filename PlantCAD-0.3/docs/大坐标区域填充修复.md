# 0.3.29 大坐标区域填充修复

此前案例中50个已计算区域有41个在自动填充时报错。曲线接缝经过面域导出后存在微小坐标差，填充模块重新创建闭环及写入HATCH时被AutoCAD 2014内核拒绝，返回`eInvalidInput`。MCP连接与该本地几何错误无关。

现在先统一直线、圆弧接缝，以共享顶点的闭合多段线保留圆弧；外环排序及面积核对使用局部坐标。原生填充若仍拒绝边界，先完整回滚失败事务，再对填充用辅助轮廓进行一次有误差上限的折线近似。近似只用于HATCH显示，原线、计算面域及统计面积不修改。

近似弦高上限取数值接缝容差8倍，与“区域对角线的百万分之一、填充比例的万分之一两者较小值”中的较大值。填充环面积偏差须在周长乘弦高上限2倍及原数值容差允许范围内；单段最多16384个分段、单环最多65536个顶点，超限提示分区。内孔分类、灰色图层、原填充替换和关联句柄保留。错误消息增加失败阶段。

## 验证范围

- 无CAD自动检查：309项。
- AutoCAD 2014案例副本：50个区域全部成功；初次填充与再次替换、8种ANSI图案、无效图案回滚、原位边界、内孔面积、原面域不变、保存重开关联等共1853项检查。
- 独立示例：填充/引线/关联表185项，字高设置与保存重开24项，共209项。
- 六组SDK编译；2015—2024对应CAD与天正宿主仍待实机验收。

案例测试的显示边界允许误差为0.02图纸单位（测试图按毫米计，即0.02毫米），原始计算面域则逐一检查面积与位置未改变。实际填充采用比该测试上限更小的弦高约束。

Core Console中原点处简单矩形的`GetHatchLinesData`也返回0，因此不将该API作为图案可见性通过的依据。已验证原生HATCH创建、重算、闭合标志、几何范围与关联持久化；桌面鼠标操作、实际显示及打印仍需复核。测试仅运行副本，没有修改或保存用户原图。

## 使用

安装0.3.29并重开CAD，选择当前植物，再运行“开始布置 → 已算面积自动填充”。已有计算面域可以直接重试，无需为这次填充修复重新扫描。此前自动补线多识别的细小区域仍需排除，本次不改变区域识别算法。

开发人员可使用自己的毫米案例图运行：

```powershell
python -B PlantCAD-0.3/developer/verify_fill_native.py --drawing "自己的案例.dwg"
```

脚本只复制源图到被忽略的测试目录，使用独立CAD配置执行；原图和生成的私有测试记录不进入安装包。
